## 2026-06-29 — Photo Gallery Investigation

**Finding:** The Photos page uses the **NextGEN Gallery** WordPress plugin.
The gallery is paginated into 5 pages. The Wayback Machine captured all 5:
- Page 1: `archive/html/photos.html`
- Page 2: `archive/html/photos-nggallery-page-2.html`
- Page 3: `archive/html/photos-nggallery-page-3.html` ← added manually
- Page 4: `archive/html/photos-nggallery-page-4.html` ← added manually
- Page 5: `archive/html/photos-nggallery-page-5.html`

**Finding:** Gallery thumbnails (small preview images auto-generated by NextGEN Gallery
and stored in `wp-content/gallery/polenet-sites_1/thumbs/`) were never archived by the
Wayback Machine — they return 404. This is not a problem for the rebuild; we have all
full-size images and will use CSS for sizing.

**Finding:** Gallery photos appear to be field site photos, labeled by station ID
(e.g. BACK, BEAR, BERP, BYRD). These match the individual site detail pages.

## 2026-06-29 — Site Detail Pages Discovery

**Finding:** The crawl discovered ~51 files named `home-page-id-XXXX.html`. These are NOT
WordPress pagination artifacts — they are **individual POLENET monitoring site detail pages**.
Each contains:
- Station ID (e.g. BACK, BEAR, BERP)
- Geographic coordinates
- Installation season/year
- Former project names and site IDs

Example: "Backer Island — Station ID: BACK — Coordinate: S 74.4304, W 102.478 — Installed: 2011-2012 season"

**Open question:** Should these 51 pages be individual pages in the rebuilt site, or
consolidated into a table on the Sites and Data page? Awaiting input from colleague.

**Noise also captured (can be ignored):**

These were discovered by the crawler following all internal links. They contain no unique
content and will not be included in the rebuild.

**Crawler issue to fix:** The crawler followed too many links including WordPress system
pages. Future runs should exclude paths matching `/wp-login`, `/feed/`, `/comments/`,
and date-based archive patterns like `/YYYY/MM/`.

## 2026-06-29 — Root Cause Identified

**The site failed due to incompatibility between the Aries WordPress theme (by United Themes,
authors Marcel Moerkens & Matthew Nettekoven) and a WordPress core update.**

The theme had not been updated to keep pace with WordPress. At some point in late 2025 or
early 2026, a WordPress update broke the theme's compatibility, taking down the site.
The database and server became compromised as a result, and no backup was available.

**Rebuild strategy:** Discard WordPress and the Aries theme entirely. Rebuild as a clean
static HTML/CSS/JS site with no server-side dependencies.
